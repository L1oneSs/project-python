## 1. Формула с номером и ссылкой

Пусть $x_i$ — наблюдение, а $n$ — размер выборки. Среднее значение рассчитывается по [формуле (1)](#eq-mean):

<a id="eq-mean"></a>

$$
\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i
	ag{1}
$$

В MkDocs формула отображается через MathJax. Число и якорь заданы явно, потому что автоматическая нумерация и cross-reference equations не являются базовой возможностью MkDocs Material. В Quarto и Sphinx/MyST для этого используются labels и штатные ссылки.

## 4. Листинг кода

Нумерация строк включена расширением `pymdownx.highlight` в конфигурации MkDocs.

```python linenums="1"
from statistics import mean

values = [1.1, 1.8, 3.2, 4.7, 6.1, 7.4]
result = mean(values)
print(f"mean={result:.2f}")
```

## 7. Как одна страница перенесена на генераторы

| Генератор | Реализация обязательных элементов | Что потребовалось дополнительно |
| --- | --- | --- |
| MkDocs + Material | Рабочая опубликованная версия: MathJax, HTML-таблица, PNG, Plotly iframe, code fence, сноска, ссылка | Ручной HTML для `rowspan`/`colspan`; явный якорь формулы; `pymdownx.snippets`; CSS для колонок |
| Sphinx + MyST | Эквивалентный исходник в `research/p2/alternatives/sphinx/index.rst`; Sphinx поддерживает labels, figures, tables, code line numbers и builders | Для библиографии нужен `sphinxcontrib-bibtex`; для колонок — `sphinx-design`; для notebook — MyST-NB; требуется отдельная Sphinx-сборка |
| Quarto | Эквивалентный исходник в `research/p2/alternatives/quarto/p2.qmd`; поддерживает equations, crossrefs, citations, executable Plotly и layout | Требуются Quarto CLI и вычислительное окружение; таблица с объединениями оформляется Pandoc/HTML; PDF может потребовать LaTeX или Typst |

Для MkDocs цена ручной разметки невелика, но часть научной семантики приходится задавать явно. Sphinx и Quarto лучше выражают научные сущности декларативно, зато требуют дополнительных инструментов и более сложного окружения.

### Как воспроизвести измерения

Локальная сборка MkDocs:

```bash
time ./.venv/Scripts/python.exe -m mkdocs build --strict
du -sh site
```

Количество внешних ресурсов можно проверить в DevTools браузера на вкладке **Network** с включённым Disable cache. Lighthouse запускается через DevTools → Lighthouse для desktop и mobile. Скриншоты нужно приложить к отчёту после этих двух запусков, потому что баллы Lighthouse не являются стабильным свойством исходного Markdown.

## 9. Что не удалось реализовать полностью

### MkDocs + Material

- автоматическую нумерацию и семантические ссылки на формулы без ручного MathJax/плагина;
- объединённые ячейки в обычной Markdown-таблице;
- автоматическую библиографию из `.bib` без дополнительного шага генерации;
- выполнение notebook как часть стандартной MkDocs-сборки.

Цена решения: ручной HTML, CSS, внешний MathJax/Plotly CDN и небольшой Python-скрипт для bibliography.

### Sphinx + MyST

В репозитории сохранён исходник, но полноценное измерение не выполнено: для него нужно установить Sphinx, MyST-Parser, `sphinxcontrib-bibtex`, `sphinx-design` и тему. Это отдельное окружение, а не функция текущей MkDocs-сборки.

### Quarto

В репозитории сохранён `.qmd`-исходник, но полноценное измерение не выполнено: нужен Quarto CLI, Python kernel и, для PDF, LaTeX/Typst. Без установки этого toolchain нельзя честно приводить время, размер output или Lighthouse.

## Вывод

MkDocs способен разместить все обязательные элементы, но для научной семантики часть решений приходится делать вручную. Sphinx + MyST и Quarto дают более естественные labels, cross-references и bibliography, однако требуют более тяжёлого окружения. Для текущего сайта MkDocs остаётся практичным вариантом, а для полноценного научного отчёта с повторным выполнением notebook предпочтительнее Quarto или Sphinx + MyST-NB.
